# Anexo K. Glosario

[[tabla: Glosario de términos y siglas]]

| Término | Significado |
| --- | --- |
| Adaptador | En la arquitectura hexagonal, implementación concreta de un puerto (por ejemplo, un repositorio sobre Prisma) |
| Alcance | Conjunto de datos que una cuenta puede ver o modificar: propio, escuelas, facultades, institución o servicio |
| API | Interfaz de programación por la que el cliente web pide y envía datos al servidor |
| Arquitectura hexagonal | Estilo que aísla las reglas del negocio de la persistencia y de los servicios externos mediante puertos y adaptadores |
| bcrypt | Algoritmo para almacenar contraseñas con un costo de cálculo ajustable |
| Bitácora de auditoría | Registro de quién hizo qué y cuándo en el sistema |
| Caso de uso | Operación del sistema que cumple un objetivo de un actor; en el servidor, una clase de la capa de aplicación |
| Ciclo | Semestre de la carrera en que se agrupan los estudiantes; cada ciclo tiene un docente tutor |
| Cobertura | Porcentaje del código ejercitado por las pruebas automáticas |
| Commit | Registro de un cambio en el control de versiones |
| DBU | Dirección de Bienestar Universitario de la UNTRM |
| Definition of Done (DoD) | Lista de condiciones que un cambio debe cumplir para considerarse terminado |
| Derivación | Envío de un caso a un servicio especializado (Escuela, Psicopedagogía, Psicología, Asistencia Social o Salud) |
| Docente tutor | Docente asignado a un ciclo para acompañar a sus estudiantes |
| Docker | Tecnología de contenedores con la que se ejecuta el sistema de forma reproducible |
| E2E (extremo a extremo) | Prueba que recorre la aplicación como lo haría una persona, desde el navegador hasta la base de datos |
| Ensayo técnico | Recorrido de las tareas de cada rol con guiones automatizados y datos ficticios, hecho por el equipo de desarrollo; no es un piloto |
| Expediente | Vista del historial de un estudiante: entrevista, sesiones, seguimientos, derivaciones y solicitudes |
| FISME | Facultad de Ingeniería de Sistemas y Mecánica Eléctrica |
| HU / TT | Historia de usuario / tarea técnica del Product Backlog |
| Integración continua (CI) | Ejecución automática de estilo, compilación y pruebas con cada cambio propuesto |
| JWT | JSON Web Token: formato de token firmado para la sesión de un usuario |
| Matrícula por periodo | Registro de qué estudiantes cursan en un periodo y en qué ciclo |
| Migración | Cambio versionado del esquema de la base de datos |
| Modo de demostración | Funcionamiento sin valor oficial: los certificados llevan marca de agua, numeración propia y no se firman ni se entregan |
| Periodo académico | Semestre de trabajo del sistema; puede estar sin abrir, vigente o cerrado |
| Permiso | Autorización para una operación concreta, por ejemplo leer estudiantes |
| Piloto | Prueba del sistema con usuarios reales autorizados; no se ha realizado |
| Prisma | Herramienta que define el esquema de datos y accede a PostgreSQL desde el servidor |
| Product Backlog | Lista priorizada de historias y tareas del proyecto |
| Protocolo | Protocolo de Acompañamiento de Tutoría N.° 01-2024-UNTRM/DBU |
| Puerto | En la arquitectura hexagonal, interfaz que el dominio exige a la infraestructura |
| Pull request | Solicitud de integración de una rama de trabajo a `develop` o `main` |
| Rol | Conjunto de permisos con un nombre (Administrador DBU, Coordinador, Docente tutor, etc.) |
| Sesión de tutoría | Encuentro individual o grupal entre un docente tutor y sus estudiantes |
| SIT | Sistema de Información para la Sistematización de los Procesos de Acompañamiento de Tutoría Universitaria |
| SMTP | Protocolo de envío de correo electrónico |
| Solicitud de tutoría | Pedido de acompañamiento del estudiante o registrado por su docente |
| UNTRM | Universidad Nacional Toribio Rodríguez de Mendoza de Amazonas |
| Versión candidata (beta) | Versión etiquetada para pruebas controladas con datos ficticios; no es la versión estable |
